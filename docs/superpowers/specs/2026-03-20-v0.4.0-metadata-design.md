# v0.4.0 — Metadata Enhancement Design

**Date:** 2026-03-20
**Scope:** Minimal, non-breaking improvements to local library metadata parsing
**Files affected:** `src/lib/metadataEnricher.ts` only

---

## Problem

When users import local MP3 files, genre is never read from the ID3 tag (TCON frame), so all tracks show "Sin género". Titles and artists sometimes appear in ALL CAPS or all lowercase due to inconsistent ID3 tagging.

## Solution

Two small changes to the existing ID3 parser in `metadataEnricher.ts`:

### 1. TCON Genre Parsing

Add TCON frame handling alongside the existing TIT2/TPE1/TALB/APIC handlers.

TCON values come in three formats:
- **Text:** `"Rock"`, `"Hip-Hop"` → use as-is (after title-casing, see below)
- **Numeric:** `"(17)"` → look up in ID3v1 genre table → `"Rock"`
- **Combined:** `"(17)Rock"` → strip the numeric prefix `(N)`, use the text portion

Implement a `resolveGenre(raw: string): string` function that handles all three formats. If the numeric code is not in the table, fall back to the raw string. If empty, return `""`. After resolving, apply `toTitleCase()` to the result.

Include the full Winamp-extended ID3v1 genre table (192 entries, IDs 0–191) as a constant map.

**Type change required:** `extractID3Tags()` currently returns `{ title, artist, album, coverUrl, duration }`. Add `genre: string` to the return type and to the result object initialization (`genre: ''`).

### 2. Auto-capitalize

Add a `toTitleCase(str: string): string` function that converts the first letter of each word to uppercase and the rest to lowercase.

Apply to `title`, `artist`, `album`, and `genre` after extraction from ID3 tags — only in the local import flow (`parseLocalFile`). Never applied to data coming from Deezer (which is already clean).

Edge cases:
- Empty string → return `""`
- Already correctly cased → no visible change
- Acronyms (e.g. "DJ") → acceptable to lowercase to "Dj" (simple implementation, no exceptions list)

---

## What is NOT changing

- No new UI components
- No store changes
- No MusicBrainz or external API calls
- No file write-back
- No batch operations
- No modal or editing UI
- No persistence changes

---

## Success Criteria

- Importing an MP3 with TCON `"(17)"` shows genre `"Rock"` in the library
- Importing an MP3 with TCON `"hip-hop"` shows genre `"Hip-Hop"` (title-cased)
- Importing an MP3 with TCON `"(17)Rock"` shows genre `"Rock"` (text portion used, title-cased)
- Importing an MP3 with title `"BOHEMIAN RHAPSODY"` shows `"Bohemian Rhapsody"`
- Importing an MP3 with no TCON frame shows `""` (same as before)
- All existing tests still pass (verify with `npm test`)
- Build clean, no new ESLint errors
